# Beredskap101 Localization and Integrity Remediation Plan

## Summary

Current status remains **not compliant**. The added findings raise the priority of localization repair from content cleanup to **release-blocking data integrity work**.

Confirmed repo facts:
- `i18n.ts` hard-defaults to `lng: 'en'`, with no persisted language preference.
- Theme changes are separate React state, but there is no regression test proving language survives dark/light toggles.
- Norwegian title/copy paths are split across `i18n.ts`, `App.tsx`, `pillarsData.ts`, `titleOptimizer.ts`, processed assets, knowledge-map data, editorial data, and component-local strings.
- The corruption includes mojibake, ASCII transliteration (`pa`, `sok`, `naermeste`, `forstehjelp`), and degraded/unidiomatic Norwegian.

## Sequential Checklist

1. Create and maintain `docs/audit-remediation-checklist-2026-06-04.md`.

3. Update the checklist after every module with exact commands, pass/fail results, remaining flags, and next allowed step.

## Key Changes

Module 1: Stop language/theme state regressions
- Persist language under `beredskap101_language_v1`; initial language must be saved preference, then browser Norwegian preference, then English fallback.
- Persist theme under `beredskap101_theme_v1`; theme changes must never call or reset `i18n.changeLanguage`.
- Add Playwright regression: select Norwegian, toggle dark/light repeatedly, navigate routes, reload, and verify the language selector and visible copy remain Norwegian. Repeat for English.

Module 2: Repair mojibake and transliteration damage
- Repair all corrupted Norwegian text in active source, tests, and verification scripts.
- Treat both mojibake and poor transliteration as failures: `Ã`, `Â`, `â€`, `�`, `pa` for `på`, `sok` for `søk`, `naermeste` for `nærmeste`, `a` for `å`, `oe` for `ø`, and `ae` for `æ`.
- Allowlist ASCII only where it is intentional: URLs, IDs, search aliases like `forstehjelp`, and technical slugs.
- Protect already-correct files such as `src/data/processedAssets.json`; no blanket conversion.

Module 3: Restore Norwegian title coverage
- Inventory every displayed title source: `pillarsData`, `processedAssets.locales.no`, `titleOptimizer`, editorial articles, knowledge-map cards, static pages, search results, pack labels, flowcharts, and checklists.
- Ensure every user-facing title has a Norwegian value when `currentLang === 'no'`.
- Remove English fallback leakage except where the source is a proper noun, book title, organization name, URL, model name, or official document title.
- Rewrite `titleOptimizer.ts` mappings so Norwegian outputs contain correct `æ/ø/å` and natural Norwegian.

Module 4: Humanize Norwegian copy
- Add a compact Norwegian product-language standard:
  - Use common Bokmål unless source material requires otherwise.
  - Prefer `førstehjelp`, `nødvarsel`, `råd`, `støtte`, `åpne`, `søk`, `tøm`, `nærmeste`, `størrelse`, `fullført`, `vær`, `på`, `nå`.
  - Avoid stiff imported phrasing, uncommon synonyms, pseudo-military language, and direct English sentence structure.
- Review medical, emergency, privacy, legal, and shelter copy manually after automated repair.
- Add sentinel tests for expected Norwegian terms and for absence of known bad forms.

Module 5: Verification gates
- Add `npm run verify:text-integrity`.
- Add `npm run verify:localization`.
- `verify:text-integrity` fails on mojibake and unauthorized ASCII transliteration.
- `verify:localization` fails when Norwegian UI shows English titles where Norwegian content exists.

## Test Plan

Run three consecutive clean passes after each module:
- `npm run verify:text-integrity`
- `npm run verify:localization`
- `npm run lint`
- `npm run build`
- `npm run ingest:validate`
- `npm run verify:module1:api` through `npm run verify:module7:contracts`
- `npm audit --audit-level=moderate`
- `npx playwright test`
- `node scripts/run_verification.js` once reconciled

Acceptance requires zero errors, warnings, mojibake flags, transliteration flags, untranslated-title flags, contrast failures, security flags, or stale test expectations.

## Assumptions

- Norwegian should be Bokmål, natural, public-service style, and human-readable under stress.
- English fallback is allowed only for legitimate names/titles or missing source data explicitly documented in the checklist.
- No Google/Gemini model or API will be introduced.
