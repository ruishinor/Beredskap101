# Beredskap101 Offline-First Implementation Roadmap

## Summary
Build this as a PWA-first offline hardening effort. Do not import Nomad’s Docker orchestration. Preserve all existing user-facing features, but make live/API/cloud-dependent features degrade safely when offline. The first milestone fixes the immediate gaps: service worker reliability, shelter map network dependencies, live feed fallbacks, and Gemini/cloud AI removal. Later milestones add content packs, local search, optional PMTiles maps, local document storage, and optional local-only AI.

## Key Interface Changes
- Keep `/api/healthz`, but allow the service worker to answer it offline with `{ status: "offline-ready" }`.
- Keep `/api/copilot/analyze`, but replace Gemini with deterministic local analysis and optional local-LLM routing only.
- Add `OfflineFeedSnapshot`: `{ fetchedAt, items, partialFailures, source: "live" | "cache" | "static" }`.
- Add `ContentPack`: `{ id, title, tier, language, category, sourceIds, assets, sizeEstimate, lastVerified }`.
- Add `LocalAiSettings`: `{ enabled, baseUrl, model, mode: "disabled" | "local-openai-compatible" }`.
- Add `SearchDocument`: `{ id, type, title, body, tags, pillarId?, urlHash?, sourceId? }`.

## Phase 0: Baseline And Guardrails
- Run current baseline checks without changing behavior: `npm run lint`, then `npm run build` only after confirming generated `dist` changes are acceptable for the working style.
- Add an implementation note to the project docs stating the non-regression rule: core guides, checklists, scenarios, shelters, source links, live feeds, contact handoff, themes, languages, and saved progress must remain available.
- Create an audit checklist for every PR or AI-assisted coding pass:
  - No required runtime dependency on external scripts, fonts, images, map tiles, AI APIs, or RSS feeds.
  - No removal of current tabs or existing content modules.
  - All offline changes have visible fallback states.
  - Typecheck and build pass.
  - Browser tested once online, once offline, once after refresh while offline.

## Phase 1: Immediate Offline Gap Fixes

### 1. Service Worker And App Shell
- Replace the current hand-written cache behavior in [sw.js](c:/00%20DEV/In%20Progress/beredskap101-app/public/sw.js) with a generated or manifest-driven precache.
- Recommended implementation: add `vite-plugin-pwa` and configure it to precache built JS, CSS, HTML, manifest, icons, SVG, and JSON assets.
- Remove the local/LAN bypass so `localhost`, `127.0.0.1`, `192.168.*`, and `10.*` can be tested offline.
- Runtime cache same-origin `GET` requests with:
  - network-first for `/api/source-feeds` and `/api/norway-news`, falling back to cached response.
  - cache-first for static assets and JSON data.
  - navigation fallback to `/index.html`.
- Make service worker return a synthetic success for `/api/healthz` when offline.
- Keep registration in production; add a documented local test path using `npm run build` plus `npm run preview`.

Acceptance:
- App loads after first install with browser devtools set to offline.
- Refreshing `/`, `/#shelters`, `/#library`, and `/#checklists` offline still renders.
- No local/LAN hostname bypass remains.

### 2. Shelter Map Offline Fallback
- Replace CDN-loaded Leaflet and remote CARTO/OSM tiles in [ShelterMap.tsx](c:/00%20DEV/In%20Progress/beredskap101-app/src/components/ShelterMap.tsx) with an offline-safe renderer.
- First milestone strategy:
  - Add `leaflet` as a local npm dependency, or remove Leaflet entirely in favor of a local SVG projection.
  - Recommended: local Leaflet dependency with no tile layer, preserving marker selection, zoom controls, geolocation marker, nearest shelter sorting, popup behavior, and route line.
  - Add a themed “offline basemap unavailable” grid/background so the map area is honest rather than blank.
- Fix the Haversine bug in `calculateDistance`; use the same correct formula as `getDistanceString`.
- Keep the existing searchable shelter list as the primary guaranteed offline path.
- Add a visible map status chip:
  - `Shelter data offline-ready`
  - `Basemap unavailable in offline fallback`
  - later `PMTiles basemap installed`

Acceptance:
- No `unpkg`, `cartocdn`, or remote tile URLs remain in shelter rendering.
- “Find nearest shelter” works offline if geolocation permission is available.
- Search, select, popup, capacity display, and shelter advisory remain intact.

### 3. Live Feeds Become Optional Online Enhancements
- Update `NorwegianNewsFeed` and `SourceLinksSection` so live fetches never block core UI.
- On successful live fetch, persist the response to local storage or IndexedDB.
- On failure, display the last cached snapshot; if none exists, show static official source cards from `sourceRegistry`.
- Remove Google favicon calls and replace them with local source initials, source badges, or bundled icons.
- Preserve live refresh buttons, source links, severity labels, and existing feed layout.
- Add copy that clearly distinguishes:
  - live data
  - cached data
  - static official-source fallback

Acceptance:
- Offline mode shows official source links and/or cached feed items without errors.
- No Google favicon network request remains.
- Live refresh still works when online.

### 4. Cloud AI Removal With Feature Preservation
- Replace the Gemini implementation in [server.js](c:/00%20DEV/In%20Progress/beredskap101-app/server.js) with deterministic local scenario analysis.
- Keep `/api/copilot/analyze` request/response compatibility:
  - Accept `{ history, context }`.
  - Return `readinessGrade`, `resilienceScore`, `avgResponseTimeSec`, `securityBlindspots`, and `operationalRecommendations`.
  - Add `provider: "deterministic-local"` or `provider: "local-llm"` as non-breaking metadata.
- Remove `@google/generative-ai` after the endpoint no longer imports it.
- Add optional local-AI support only through user-configured local OpenAI-compatible/Ollama endpoints.
- Never use external AI fallback.
- Update README to remove the contradiction between “no server-side AI calls” and the old Gemini proxy.

Acceptance:
- No Google/Gemini package or import remains.
- `/api/copilot/analyze` still returns useful structured analysis.
- Missing local AI never breaks simulations or scenarios.

### 5. Connectivity Semantics
- Keep the existing `ONLINE`, `DEGRADED`, `OFFLINE` labels for UI compatibility.
- Change heartbeat behavior so static offline PWA mode does not falsely imply the app is broken when `/api` is unavailable.
- Prefer app-readiness checks over internet checks:
  - service worker health response
  - cached shell availability
  - optional backend status when a backend exists
- Add a small “offline ready” indicator separate from “live feeds reachable” if needed.

Acceptance:
- A static offline deployment can show “offline ready” even without live API access.
- Live feed failures do not flip the whole app into a broken state.

## Phase 6: Optional Local-Only AI
- Add a settings panel for local AI:
  - disabled by default
  - base URL
  - model name
  - test connection
  - clear settings
- Support OpenAI-compatible local endpoints such as Ollama, LM Studio, or llama.cpp.
- Recommended default local endpoint: `http://localhost:11434/v1`.
- Recommended small models:
  - Gemma 3 1B or 4B for modest machines
  - Qwen 2.5 3B for compact instruction tasks
  - larger models only as user-selected options
- Use AI only for assistive features:
  - explain a checklist
  - summarize local content
  - generate a household drill
  - analyze scenario history
- Always provide deterministic fallback output.
- Add “AI answer is advisory” warnings for medical, safety, legal, and emergency decisions.
- For RAG-lite, inject local search results as context before calling the local model.
- Do not add Qdrant to the PWA core; reserve vector databases for a later optional companion module.

Acceptance:
- App is fully functional with AI disabled.
- AI calls never target cloud APIs.
- Local AI failure returns a clear fallback, not a broken UI.

## Assumptions And Defaults
- Deployment priority is PWA-first.
- First map milestone is shelter-safe fallback, not PMTiles.
- AI is optional local-only and disabled by default.
- No Nomad Docker orchestration will be adopted.
- Existing features must be preserved; cloud/network dependencies should be wrapped, replaced, or degraded, not used as required runtime paths.
- Large map/content packages should be optional modules, not mandatory core bundle contents.
