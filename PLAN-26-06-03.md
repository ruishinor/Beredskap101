# Beredskap101 Offline, Feeds, UI, and Content Remediation Roadmap

## Summary
- Baseline: Vite/React app, TypeScript check currently passes with `npm run lint`.
- Implement in strict sequence: map/offline package, feed reliability, UI layout, reading/footer updates, then content-pipeline remediation.
- After each module, run the relevant checks 3 consecutive times with 100% pass rate and no console errors, TypeScript errors, build warnings, accessibility blockers, or Playwright failures before proceeding.

## Key Changes

### 1. Offline PMTiles Package and Shelter Map
- Add `public/maps/pmtiles-manifest.json`. Vite serves this as `/maps/pmtiles-manifest.json`, which is already the path expected by `MAP_PACK_MANIFEST_PATH`.
- Use this manifest schema:
```json
{
  "version": 1,
  "packageId": "norway-basemap-v1",
  "mode": "local-public-file",
  "styleUrl": "/maps/norway-style.json",
  "installedAt": "2026-06-03T00:00:00.000Z",
  "lastUpdatedAt": "2026-06-03T00:00:00.000Z",
  "staleAfterDays": 180
}
```
- Also place the actual PMTiles archive and style file under `public/maps`, for example:
  - `public/maps/norway.pmtiles`
  - `public/maps/norway-style.json`
- The style must reference the archive with PMTiles protocol syntax:
```json
{
  "version": 8,
  "sources": {
    "norway": {
      "type": "vector",
      "url": "pmtiles:///maps/norway.pmtiles",
      "attribution": "© OpenStreetMap contributors"
    }
  },
  "layers": []
}
```
- Replace `layers: []` with layer definitions matching the actual vector layer names in the PMTiles metadata. The manifest alone enables detection, but the renderer will still fail if `styleUrl` or the `.pmtiles` file is missing or invalid.
- Remove the `Topo` feature permanently from [ShelterMap.tsx](</c:/00 DEV/In Progress/beredskap101-app/src/components/ShelterMap.tsx>): remove the `topographic` mode, `kartverket-topo` candidate, `Topo` label, helper text, test references, and fallback ordering.
- Backwards compatibility: if localStorage contains `beredskap101.shelterMap.layerMode.v1 = "topographic"`, treat it as `street` and overwrite it on next save.

### 2. News Feeds, Cache, Print, and Save
- Current feed behavior to document in UI/dev notes:
  - `/api/norway-news?limit=100` is fetched on component mount and manual refresh only. No polling interval exists.
  - Server cache header: `s-maxage=300, stale-while-revalidate=1800`.
  - `/api/source-feeds` is fetched on mount/language change only. Server cache header: `s-maxage=900, stale-while-revalidate=3600`.
  - Service worker uses network-first caching for both API paths.
- Current aggregation parameters:
  - No keyword filter is currently used.
  - `/api/norway-news` sources: NRK, Digi.no, Politiloggen, MET Norway alerts, DSB.
  - Severity labels: `Nyheter`, `Teknologi`, `Politiloggen`, `Farevarsel`, `Beredskap`.
  - `limit` defaults to 20, accepts `all`, and is clamped to 1-100. UI fetches 100 then locally displays 5, 10, 20, 50, 100, or all.
  - `/api/source-feeds` fetches up to 4 items per official source.
- Common failure criteria to surface:
  - Remote non-2xx responses, 15s timeout, XML/Atom/RSS parse changes, CORS/network failure, Politiloggen HTML/Next.js data shape changes, missing RSS endpoints, malformed dates, and empty MET alert payloads.
  - `no_feed` is expected for sources without confirmed RSS endpoints.
- Add a shared feed cache utility with a 3-day retention window for retrieved feed snapshots. Apply to localStorage and service-worker API cache responses for feed/news content, not to the static PWA shell.
- Add `Print` and `Save JSON` controls to Norwegian news and Official Sources. Saving must be 100% client-side with `Blob` download. Printing must HTML-escape all feed fields and never use untrusted feed HTML.
- Normalize all ISO timestamps through one formatter using `Intl.DateTimeFormat`, `nb-NO` or `en-GB`, `Europe/Oslo`, day/month/year/hour/minute, and short time zone. Remove raw `toISOString().replace(...).slice(...)` display.

### 4. Content Audit Remediation
- Treat the audit finding as a pipeline trust defect. The repeated checklists, course modules, generic stats, and lightly topic-labeled protocols must be fixed at generation/validation level, not hidden in the viewer.
- Update the processed-asset ingestion flow to reject or flag component reuse across unrelated source assets. Add checks for duplicate checklist arrays, duplicate course module theory/goals, constant stats, and protocol procedures with only title injection.
- Add source-specific evidence fields to the asset contract: `sourceDerivedClaims`, `domainActions`, `validationNotes`, and `humanReviewStatus`. Existing UI must remain backwards compatible when these fields are missing.
- For regenerated content, require every checklist/protocol/module to include concrete domain actions from the source topic. Examples: first aid assets mention bleeding control and kit access; GDPR assets mention lawful basis, sensitive data, retention, access control, and breach escalation.
- Remove or label unsubstantiated analytic scores. Until real per-asset scoring exists, show stats as metadata only or mark readiness/complexity as “not assessed”.
- Use deterministic extraction and rule checks first. If AI assistance is used, keep it local or self-hosted where possible, minimize prompts, exclude personal data, and require HITL review before publishing. Do not use Google or Gemini APIs.

## Verification Protocol
- Per module, run 3 consecutive clean passes:
  - `npm run lint`
  - `npm run build`
  - `npm run ingest:validate`
  - updated Playwright UI regressions
  - updated offline smoke test
- Add Playwright assertions for:
  - offline local search appears after the knowledge map
  - no `Topo` button exists, old `topographic` localStorage migrates to `street`
  - missing/invalid PMTiles package degrades without breaking shelter search
  - valid manifest + style initializes offline package state
  - feed cache older than 3 days is purged
  - print/save buttons work without network calls
  - feed timestamps are human-readable, not raw ISO
  - Official Sources cards do not overlap on desktop or mobile
  - footer targets are at least 44px and keyboard focus is visible
  - dark/light mode still works
- Adversarial review cases: corrupt localStorage, malformed feed payloads, malicious feed text/link values, missing RSS endpoints, invalid PMTiles style, stale manifest, long source titles, and offline mode after first load.
- Retrospective gate: after the third clean pass, record what failed during implementation, what was hardened, remaining residual risks, and whether any audit issue remains unresolved.

## Assumptions
- “The After series, 3 books” means the original John Matherson trilogy: *One Second After*, *One Year After*, and *The Final Day*.
- The three-day cache rule applies to retrieved feed/news snapshots and source-feed API caches, not the static app shell or authored offline preparedness content.
- The PMTiles archive itself is not committed unless its size is acceptable for the repository. If large, the app should keep the manifest/style documented but the package file should be supplied during deployment or local setup.
